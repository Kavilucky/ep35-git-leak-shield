ЧТО В АРХИВЕ
  .pre-commit-config.yaml  - подключает Gitleaks как хук перед каждым коммитом
  .gitleaks.toml           - стандартные правила Gitleaks + пропуск тестов и моков
  .gitleaksignore          - список отпечатков заведомо фиктивных находок
  install_shield.bat       - установка для Windows
  install_shield.sh        - установка для Linux и macOS
  Инструкция.txt           - этот файл

ПОЧЕМУ УДАЛИТЬ СТРОКУ С ПАРОЛЕМ НЕДОСТАТОЧНО
Git хранит всю историю. Новый коммит «без пароля» не стирает старый: прежний коммит
остаётся в репозитории, его видно командой  git log -p  или  git show <хеш>.
Если репозиторий публичный или вы уже сделали push, считайте ключ украденным.
Что делать, если ключ уже ушёл в сеть:
  1. Сразу ОТОЗВАТЬ ключ у провайдера (OpenAI, AWS, GCP и т.д.) и выпустить новый.
     Это главное действие, оно важнее всего остального.
  2. Проверить счета и логи использования ключа.
  3. Потом вычистить историю (git filter-repo или BFG) и сделать принудительный push.
     Это не отменяет пункт 1: кто-то мог успеть склонировать репозиторий.

ПРАВИЛО .env
  - Секреты держите в файле .env (или в менеджере секретов), а не в коде.
  - Добавьте в .gitignore строки:   .env   *.env   secrets/
  - В репозиторий кладите только .env.example с пустыми значениями.

УСТАНОВКА
Нужны Git и Python 3. Откройте консоль в папке вашего репозитория.
  Windows:        путь\к\распакованному\install_shield.bat
  Linux / macOS:  bash путь/к/распакованному/install_shield.sh
Скрипт поставит pre-commit, скопирует конфиги в корень репозитория (существующие файлы
не перезаписывает) и выполнит  pre-commit install.
Вручную то же самое:
  pip install pre-commit
  pre-commit install
Первый запуск скачивает Gitleaks, нужен интернет.

ПРОВЕРКА
  pre-commit run --all-files
Чтобы увидеть блокировку, добавьте в тестовый файл строку с правдоподобным, но
ФИКТИВНЫМ ключом и выполните git add и git commit. Если правило не сработало на
выдуманном значении, это нормально: Gitleaks смотрит на формат провайдера и энтропию.
Боевые ключи для проверки не используйте.

ЕСЛИ ХУК ЛОЖНО СРАБОТАЛ
Для тестовых значений занесите отпечаток из вывода Gitleaks в .gitleaksignore или путь
в allowlist файла .gitleaks.toml. Боевой ключ в исключения не вносить, его отзывают.

ЧЕСТНЫЕ ОГРАНИЧЕНИЯ
  - Хук локальный. Его обходит  git commit --no-verify. Он не устанавливается сам
    после  git clone: каждый разработчик запускает  pre-commit install.
  - Gitleaks ищет известные форматы и высокую энтропию. Нестандартный секрет может
    пройти, а безобидная строка может дать ложное срабатывание.
  - Второй слой защиты: проверка в CI и включённое сканирование секретов на хостинге.
  - Скорость сканирования зависит от размера изменений и машины. Автор замер не публикует.
  - Скорость, с которой боты забирают ключи («четыре секунды» в ролике), это оценка
    сценария, не замер. Суммы из ролика (3 000 $, пуши банка) это пример, не статистика.
  - Скрипты и конфиги автором не запускались на чистых системах, проверьте на тестовом
    репозитории. Версия Gitleaks (rev в .pre-commit-config.yaml) могла устареть: сверьте
    с https://github.com/gitleaks/gitleaks/releases
  - Не заменяет аудит безопасности.
