# Защита от утечки боевых ключей в Git: Gitleaks + pre-commit

Набор файлов к ролику «Защита от утечки боевых API-ключей в Git». Pre-commit хук запускает Gitleaks по staged-файлам перед каждым коммитом и блокирует коммит, если находит ключ, токен или пароль: коммит с секретом не создаётся и в сеть не уходит.

Канал с материалами: [@ByteAutomate_AI](https://t.me/ByteAutomate_AI). Аудит безопасности и чистка репозиториев под ключ: @konstantin_100.

```bash
git clone https://github.com/Kavilucky/ep35-git-leak-shield && cd ep35-git-leak-shield
```

## Что внутри
| Файл | Для чего |
|---|---|
| `.pre-commit-config.yaml` | подключает хук Gitleaks (`--redact`: значения секретов в выводе скрыты) |
| `.gitleaks.toml` | стандартные правила Gitleaks плюс пропуск каталогов тестов, моков и примеров |
| `.gitleaksignore` | отпечатки заведомо фиктивных находок (по умолчанию пуст) |
| `install_shield.sh` | установка для Linux и macOS |
| `install_shield.bat` | установка для Windows |
| `Инструкция.txt` | подробная инструкция для новичка |

## Почему мало удалить строку с паролем
Новый коммит «без пароля» не стирает старый: прежняя ревизия остаётся в истории и читается командами `git log -p` и `git show <хеш>`. Если секрет уже попал в публичный репозиторий, считайте ключ украденным:
1. отзовите ключ у провайдера и выпустите новый (главное действие);
2. проверьте счета и логи использования;
3. затем чистите историю (`git filter-repo` или BFG) и делайте принудительный push. Это не отменяет пункт 1.

## Установка
Нужны Git и Python 3. Откройте консоль в папке **вашего** репозитория и запустите скрипт из этого набора:
```bash
bash путь/к/install_shield.sh        # Linux и macOS
путь\к\install_shield.bat            # Windows
```
Скрипт ставит `pre-commit`, копирует три конфига в корень вашего репозитория (существующие файлы не перезаписывает) и выполняет `pre-commit install`. Вручную то же самое:
```bash
pip install pre-commit
pre-commit install
```
Первый запуск скачивает Gitleaks, нужен интернет. Проверка: `pre-commit run --all-files`.

## Правило .env
Секреты держите в `.env` или менеджере секретов. В `.gitignore` добавьте `.env`, `*.env`, `secrets/`. В репозиторий кладите только `.env.example` с пустыми значениями.

## Как это работает
Gitleaks ищет форматы ключей известных провайдеров по регулярным выражениям и оценивает энтропию строки. Нашёл секрет: код выхода 1, `git commit` прерывается. Ложное срабатывание на тестовых значениях закрывается отпечатком в `.gitleaksignore` или путём в allowlist файла `.gitleaks.toml`. Боевые ключи в исключения не вносят: их отзывают.

## Честные ограничения
- Хук локальный. Его обходит `git commit --no-verify`, и он не ставится сам после `git clone`: каждый разработчик запускает `pre-commit install`.
- Gitleaks ищет известные форматы и высокую энтропию: нестандартный секрет может пройти, безобидная строка может дать ложное срабатывание. Вторым слоем нужны проверка в CI и включённое сканирование секретов на хостинге.
- Скрипты и конфиги **автором на чистых системах не запускались**; проверьте на тестовом репозитории. Версию Gitleaks (`rev` в `.pre-commit-config.yaml`) сверьте с [релизами](https://github.com/gitleaks/gitleaks/releases): значение могло устареть.
- Скорость сканирования зависит от размера изменений и машины; автор замер не публикует. Скорость ботов («четыре секунды» в ролике) и суммы (3 000 $) это оценки сценария, не замеры.
- Не заменяет аудит безопасности.
